# 按月净值期初锚点：推广 back_solved 反推 + assumption 透出

## Context

按月净值计算（API-032，GET /nav?period=YYYY-MM）目前除首月外经常因"缺期初资产锚点"整月 blocked。根因：[_initial_cash](file:///Users/bean/Documents/AI/stock-analyze/backend/packages/review/src/stock_review/application/bridge.py#L117-L127) 只有两条锚定路径——区间前余额行（statement）、全历史首行反推（back_solved）；首行非余额行且区间前无余额行时即 blocked。

规划阶段已论证（用户确认）：期初持仓数量由 FIFO open lots 纯流水推导，永不缺；期初持仓市值缺行情走独立 blocked 分支；**唯一缺口是期初现金**。只要全历史存在任意一条余额行，推广反推即可锚定任意月份；月末结转表/每日资产表属于性能物化层，不增加覆盖率且引入尾部失效传播风险，本期不做。

目标：任意月份只要全历史有任意余额行即可构建成功；期初来源以 `summary.assumption` 透出（`statement` | `back_solved`）；全历史零余额行保持 blocked（对应 PRD `MISSING_CASH_BALANCE` 场景）。

## 改动点

### 1. 契约先行 — `docs/architecture/v2/API-Catalog.md`

- §2 API-032 响应字段：`NavSummary` 增加 `assumption`（`"statement" | "back_solved"`，blocked 时为 null）。
- §4 关键资源 Schema 的 NavSeries 摘要同步补该字段。
- §6 验收矩阵加一条：「首行非余额行、区间内含余额行的月份 → 构建成功且 `summary.assumption="back_solved"`，期初现金 = 余额行余额 − 该行发生额 − 区间内该行之前流水发生额之和」。

### 2. 推广 `_initial_cash` — `backend/packages/review/src/stock_review/application/bridge.py`

签名改为返回 `(cash_units, source) | None`，`source ∈ {"statement", "back_solved"}`：

1. **statement（现状保持）**：`period_start` 前最后一条余额行 → 直接取余额。
2. **back_solved（推广）**：取 `period_start` 当日或之后**第一条**余额行 B（离锚点最近、推导链最短），
   `initial_cash = B.balance − B.amount − Σ{t.amount : period_start ≤ t.date 且 t 按稳定序排在 B 之前}`。
   稳定序即 `balances_ordered` 的 (trade_date, line_no NULLS FIRST, 补差优先, id)；累加到 B 行为止。
   现行"全历史首行反推"是本公式的特例（B=trades[0] 时 Σ=0），行为兼容。
3. 全历史无任何余额行 → `None`（调用方维持 blocked）。

`bridge_for_period` 调用点同步解构，source 忽略（桥接有 residual 自校验，status 逻辑不变；API-027 契约不动）。

### 3. NAV 应用层 — `backend/packages/review/src/stock_review/application/nav.py`

- `compute_nav_points`：step 1（零余额行 → blocked「无现金余额锚点」）保持；step 2 改用新签名；删除"无法确定期初现金（无区间前余额且首行非余额行）"分支（推广后为死代码）。
- 返回值/`NavComputeResult` 增加 `assumption: str | None`（blocked 时 None）。assumption 仅响应透出，**不落 nav_daily**（每次 GET 同事务现算现取，无需新增列/迁移）。
- `compute_and_store_nav` 透传。

### 4. API 边界 — `backend/services/api`

- `schemas.py`：`NavSummaryOut` 增加 `assumption: Literal["statement", "back_solved"] | None = None`。
- `routers/nav.py`：summary 组装填 `result.assumption`（`result.series is None` 时 None）。
- 依次执行 `make api-snapshot` → `make api-check` → `make sdk`。

### 5. 前端 — `frontend/apps/web/src/pages/Nav.tsx` + `Nav.test.tsx`

- SDK 类型随 `make sdk` 更新；`result.summary.assumption === "back_solved"` 时在既有 notice 区域追加一句「期初资产为反推值（assumption=back_solved）」。
- `Nav.test.tsx` 的 mock Nav 数据补 `summary.assumption`。

### 6. 测试

- `backend/tests/unit/review/test_nav_application.py` 新增：
  - 首行非余额行 + 区间内首条余额行 → 构建成功、assumption=back_solved、期初现金与手工期望值逐分一致；
  - 区间前有余额行 → assumption=statement（现有用例行为不变）；
  - 全历史零余额行 → blocked 且 assumption 缺省。
- bridge 单测（涉及 `_initial_cash` 签名）同步更新。
