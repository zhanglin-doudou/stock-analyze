## 1. 背景与问题

### 1.1 背景

用户（个人投资者）持有完整的股票生涯流水明细（券商导出交易账单），希望借助软件能力分析与提升自己的**股票选择**与**交易执行**水平。

**本版新增的硬约束（v1.0 缺失）**：主要使用者是**非程序员个人投资者**。他会用 Excel、会看行情软件，但**不写 SQL、不开 Postman、不装数据库服务器、不会用命令行**。这不是偏好问题，是产品能否成立的前提——它直接决定 §4.3 的形态约束与 FR-L1/FR-D1 的必要性。

### 1.2 核心洞察

流水明细的核心价值**不在对账**，而在于把三个维度拆开独立度量：

| 维度 | 度量问题 | 主要产出 |
|---|---|---|
| **选股能力** | 买入的股票本身好不好？（财务质量、买入后超额收益、板块归属、风格分段） | 买入事件 cohort 的 BHAR、行业配置 vs 选择 |
| **择时能力** | 买点和卖点好不好？（买在趋势中还是下跌中、追涨分位、卖飞率、卖出后走势） | 追涨分位、卖飞率 z 分数、β/α |
| **行为偏差** | 是否在系统性犯同样的错？（处置效应、摊平、频率-收益负相关） | PGR/PLR、过度交易、集中度 |

**本版新增第四个必须回答的问题（v1.0 缺失，评审双方共识）**：以上三域都是"体检"，用户真正要的是**病因**——

> **Q0：我这个月到底为什么亏？** 亏损金额拆解到「选股 / 板块 / 买点追高 / 卖点太早 / 手续费」五因子，并给出占比最大的一项。没有归因，三域就只是三个数字。

### 1.3 原始诉求（MVP 四问 + 第 0 问）

1. 净值曲线 vs 基准指数 ——我到底跑赢了吗？（**必须带基准代码与 β，绝对收益优先展示**）
2. 胜率 × 盈亏比 × 平均持仓天数 × 盈亏集中度 ——四个数字定性我的风格（**必须带样本量 N 与置信区间**）
3. 手续费累计占比——交易成本是朋友还是敌人？（**必须有分母与"费用回本门槛"**）
4. 处置效应检测——赚钱仓和亏钱仓的持有天数差（**主口径改为 PGR/PLR，并转化为行为规则卡**）
5. **（新增）归因拆解——我这个月亏在哪？下个月只改哪一件事？**

**产品定位**：在 MVP 四问之上，构建完整的「数据底座 → 三域度量 → 归因 → 行动闭环」。**报告是产品，指标只是原料。**

## 2. 产品目标

| 编号 | 目标 | 可验证的成功标准 |
|---|---|---|
| G1 | 把券商流水从"对账单"升级为"交易能力度量系统" | 三域指标全部可输出；30 回合分层抽样核对：回合 pnl 差额 ≤0.01 元、收益率差额 ≤1bp、FIFO 配对 `trade_id` 集合 100% 一致 |
| G2 | 数据可信 | 每次导入自动对账，断链 100% 检出（阈值 0.01 元）；任一数字可追溯（`metric_id` + `definition_version` + `data_as_of` + `n`）；净值日收益与独立复算差额 ≤1bp |
| G3 | **用户能打开、能看懂、能拿走** | 从零安装到看见首屏 ≤10 分钟，**全程无需命令行与数据库安装**；任一结论可读为"一句人话 + 一句算法 + 可下钻明细"；**每月可导出并保存一份月度复盘报告** |
| G4 | 复盘以对话完成 | 自然语言提问，回答中每个数字可追溯；金额由本地计算填充，LLM 负责组织语言；关闭网络时金额类问题仍可答 |
| G5 | 数据自主可控 | 全链路本地；账单原件仅本地归档；**一键导出全量 + 每周自动备份 + 可整体迁移到新机器** |
| G6 | 结论不被统计噪声误导 | 所有比率附 N 与 95% CI；N<10 只出原始值不出结论；日频 <60 交易日不输出夏普/回撤/IR |

> G1~G6 均需在对应里程碑的验收中给出可判定证据；「与手工抽查一致」这类表述已全部替换为带容差的具体判据（见各 FR 验收与 NFR-7）。

## 3. 用户与使用场景

### 3.1 用户

单一个人用户（系统 seed 唯一记录，`name='root'`、`user_id=100000`）。**无账号密码登录、无权限体系**——`user_id` 只是数据分区标签，服务仅绑定本机（`127.0.0.1`）。后续对 C 端开放时再增加密码、角色与权限（表结构不变，仅加 API 中间件）。

**使用者能力假设**（决定产品形态）：非程序员；数据量级为 10 年 ≤ 5 万行流水；设备为个人电脑；对隐私敏感但接受本地存储。

### 3.2 核心场景

**场景 A｜首次使用（关键路径，v1.0 缺失）**
```
双击启动应用 → 浏览器自动打开 127.0.0.1:8787 → 首页引导"导入第一份账单"
→ 选择文件 → 自动识别表头 → 点两下确认列映射（并记住）
→ 结果页："导入 328 行，成功 325，3 行没看懂 [查看]"
→ 若首行不是买入："你的账单从 2023-01-03「利息归本」开始，净值起点为 2023-01-03，此前收益不计入。[继续]"
→ 首页出现 5 张卡片
```
成功标准：全程无命令行、无数据库安装、无报错停顿；失败步骤有明确下一步。

**场景 B｜月度导入（日常）**
```
每月导出账单 → 拖入页面 → 自动去重 → 结果页可【撤销本次导入】
```

**场景 C｜周五晚复盘（核心价值）**
```
打开首页 → 5 张卡片（净值/四数字/费用/处置效应/最赚最亏 3 笔）
→ 点任一数字 → 下钻到"涉及哪几笔、怎么算的"
→ 看首页顶部一句结论："你这个月亏在追高买入，不是选错票。下月只做一件事：不买当日涨幅榜前 50 的票。"
```

**场景 D｜生成月报（唯一可带走的交付物）**
```
点【生成本月复盘】→ 一页 HTML（含图表）→ 可打印/存 PDF/导出长图
→ 内容：本月交易 N 笔、收益 X 元、vs 基准、亏最多 3 笔及共性、第 N 次重复错误、下月一条行动
```

**场景 E｜写交易日志（新增，闭环）**
```
买入前 30 秒记一句"我为什么买" → 卖出后自动弹"当初这个理由还成立吗？" → 季度出"我说的 vs 实际发生的"
```

**场景 F｜换电脑/备份（新增）**
```
设置页 → 【一键导出全量（Excel + JSON）】/【立即备份】→ 每周自动备份到指定目录
```

**场景 G｜对话提问（P1，最终形态）**
```
点固定问题按钮（或自由输入）→ 回答 = 结论 + 依据 + 【看流水】
```

## 4. 产品组成与形态约束

### 4.1 产品组成（三层）

| 层 | 模块 | 一句话定位 | 用户可见性 |
|---|---|---|---|
| 数据底座 | 交易账单系统（Trade Ledger） | 交易数据唯一事实源 | 间接（通过导入页与结果页） |
| 度量层 | 个人交易复盘系统（Trading Review） | 三域度量 + 归因 + 可信度 | 只读（通过看板与报告） |
| 交付层 | 看板 / 月报 / 对话 | 把数字变成结论与行动 | 直接 |

### 4.2 工程形态（对用户不可见的部分不写进产品需求）

- 两模块同仓库（uv workspace Monorepo）开发，**但对用户表现为"一个应用、一次启动"**。
- **默认部署：单进程 + SQLite 单文件**（`~/Documents/交易复盘/review.db`），表以 `ledger_` / `review_` 前缀区分逻辑库。
- **可选部署**：PostgreSQL 双 schema（`ledger` / `review`），仅作为未来云端/多用户的可选 profile（`docker compose --profile pg`），**不是个人用户的默认路径**。
- v1.0 的「变更流 / 水位线 / 镜像 / 墓碑」不再作为产品需求：单用户单库场景下，度量层直接读视图即可。若未来引入跨机同步，再另立需求。

### 4.3 形态硬约束（v1.0 缺失，本版 P0）

1. **零数据库安装**：不得要求用户安装 PostgreSQL 或任何数据库服务。
2. **双击可用**：提供一键启动入口（macOS `.command` / Windows `.bat` / 备选 `docker compose up`），启动后自动打开浏览器。
3. **有页面**：M0 起即可打开只读页面；不允许"只交付 API 文档"。
4. **不做重前端工程化**：不引入前端路由、状态管理、组件库、前后端分离；采用服务端渲染的只读单页即可。

## 5. 功能需求

> 优先级：P0（M0–M1 必须）/ P1（M2）/ P2（M3 及以后）。
> **每条验收均为可判定判据**；通用容差常量：金额 `ε_amt = 0.01 元`、收益率 `ε_r = 1bp`、区间累计收益 `ε_cum = 5bp`、年化交易日 `A = 244`。

### 5.1 数据底座（交易账单系统）

产品层面仅支持 **A 股华泰证券普通账户**交易账单；程序结构上预留 A 股/港股/美股、券商、普通/融资账户的区分（本期仅实现 A 股普通账户）。支持真实账单格式（`.xls` / `.xlsx` / `.csv`）。每个用户的起始账单数据为其任意可导出的最早流水（**不再要求必须为买入**）。

#### FR-L1 安装、启动与部署形态 —— P0

- 一键启动入口 + 自动打开浏览器；数据目录固定为 `~/Documents/交易复盘/`（可在设置页修改）。
- 首次启动自动建库、自动迁移、无需任何外部服务。
- **验收**：在干净机器上（仅装 Python 或 Docker）从双击到看到首屏 ≤10 分钟且零命令行；重复启动不重复建库；数据目录可迁移后正常启动。

#### FR-L2 用户数据分区 —— P0

- 系统 seed 唯一用户（`name='root'`、`user_id=100000`）；所有数据带 `user_id`（BIGINT，从 100000 起自增）；不做登录与权限。
- **验收**：API 均接受 `user_id` 参数（默认 `100000`）；`users` 表仅一行 seed 数据；**不为此写任何用户管理 UI**。

#### FR-L3 账单导入（向导 + 两模式 + 可撤销）—— P0

**3.1 导入向导（v1.0 缺失）**
- 自动识别文件表头与前置标题行（华泰账单前部含客户姓名/资金账号/对账期间等 2~5 行）。
- 列映射：自动匹配后由用户确认/调整，**记住该券商的映射**供下次自动套用。
- 可下载 Excel 模板。

**3.2 字段与格式兼容**
- 13 个固定字段（日期/币种/股东账号/证券代码/证券名称/摘要/成交数量/成交均价/佣金/印花税/其他费/发生金额/资金余额），列名接受常见别名（如「成交日期」→ 日期、「成交数量」→ 数量）。
- 日期接受多种格式：`20230103`、`2023-01-03`、`2023/1/3`、Excel 日期序列号。

**3.3 两种更新模式（v1.0 的三种收敛为两种）**
- **全量导入（日常）**：行级幂等，重复行自动跳过（去重规则见附录 B）。
- **区间替换（修复模式）**：指定日期区间内以新账单为准，旧数据软删（保留可追溯）。入口折叠在「高级/修复」中，不作为日常路径。

**3.4 批次与撤销（v1.0 缺失）**
- 记录导入批次 `import_batch`（时间、文件名哈希、总行数、新增数、跳过数、隔离区行数、模式）。
- 导入结果页提供**【撤销本次导入】**：撤销该批次新增的数据（软删），不影响其他批次。
- **验收**：① 重复上传同一文件 0 新增；② 同键多笔（同日同价同量）按出现次数去重而非误判；③ 撤销后数据回到导入前状态（行数与指标复算一致）；④ 区间替换后旧数据软删可查、新数据生效；⑤ 导入历史可按批次列表查询。

**3.5 文件自检（v1.0 缺失）**
- 缺少「资金余额」列时明确提示：「你导入的可能是交割单，对账将不可用（收益仍可计算）」并降级，不静默失败。
- 缺少必需列时给出「缺哪列、去哪找、怎么办」。

#### FR-L4 交易数据维护与修复 —— P0

- 单行人工修正（PATCH）、软删（DELETE，`deleted=true`）、恢复；删除历史永不物理清除。
- 单条新增走 PATCH/POST 接口（v1.0 单列的「单条插入模式」并入此处）。
- **验收**：软删行不参与下游计算，但可在「已删除」筛选下查看并恢复；恢复后指标复算与原值一致（diff=0）。

#### FR-L5 摘要分类与隔离区 —— P0

**5.1 分类规则**
- 「摘要」经可配置规则表分类为：
  - **交易流**：买入、卖出；
  - **公司行为流**：分红/股息、送股、送转、配股、红利税；
  - **资金流**：银证转账（转入/转出）、利息归本；
  - **打新流（本版新增）**：申购中签、新股缴款、新股卖出（常无证券代码，仅有发生金额）；
  - **未匹配**：进隔离区并在导入响应中告警，**绝不静默丢弃**。

**5.2 打新与利息的处理（v1.0 缺失，直接影响净值）**
- 打新缴款计入资金占用与现金流出，中签股份按新股上市日建仓；不参与普通回合配对，但计入净值与资金利用率。
- 利息归本计入**内部收益**（不是外部现金流，见 FR-R3.2）。

**5.3 规则维护方式**
- 规则存配置文件，设置页提供简单表格编辑（v1.0 的「规则经 API 维护」降级）。
- **验收**：所有真实账单摘要类型可归类；未知摘要 100% 进隔离区且导入响应含行号；修改规则后可按区间重跑分类；打新类流水不导致净值断链。

#### FR-L6 对账自证（分级阻断 + 用户可见）—— P0

**6.1 余额链校验**
- 利用账单自带逐行「资金余额」做现金余额链校验（上一行余额 ± 发生金额 ≈ 本行余额），断链精确定位到行。

**6.2 分级处置（v1.0「FAIL 不阻断」修订为分级）**
- 断链区间内的**资产类指标**（净值、回撤、夏普、超额收益）→ **硬阻断**，输出 `NAV_UNRELIABLE` 并带断点信息。
- 断链区间**外**的回合级指标 → 仍输出，但标注「含 N 笔可疑」。
- 阻断原因**必须在页面红字 + 人话呈现**（不能只藏在 API 响应里）：「3 月 12 日前后余额对不上，疑似漏一笔转账，本月收益暂不可信。[查看断点行]」。

**6.3 验收**
- 断链样例 fixture 检出率 100%，给出断点 `trade_id` 与期望/实际值，金额误差 ≤`ε_amt`。
- 页面在阻断状态下确实不显示可能误导的收益结论。

#### FR-L7 数据主权：导出 / 备份 / 迁移 —— P0（v1.0 缺失）

- 一键导出全量（Excel + JSON，含元数据与口径版本）。
- 每周自动备份到用户指定目录（保留 N 份，可配置）。
- 支持整体迁移：在新机器指向备份目录即可恢复。
- **验收**：导出→清空→导入后，行数、回合数、净值序列完全一致（diff=0）；备份失败有可见告警；恢复后应用可正常启动。

#### FR-L8 查询 API —— P0

- 流水分页查询（账户/代码/日期/方向/是否含已删）、回合查询、指标查询。
- **变更流 `GET /trades/changes` 降为 P2**（内部可选实现）；本期度量层直接读视图/函数调用。
- **验收**：查询结果与页面展示一致；分页边界无重复/遗漏。

### 5.2 度量层（个人交易复盘系统）

#### FR-R1 数据同步 —— P0（降级为内部实现）

- 默认形态下，度量层与账单层同库同进程，通过只读视图/函数调用取数，**不做跨进程镜像同步**。
- 若启用 PostgreSQL 双 schema 部署，则为只读跨 schema 查询，**不引入水位线与墓碑字段**。
- **验收**：单据写入后指标复算结果与直接读表一致（diff=0）；无"同步延迟导致的空窗"。

#### FR-R2 期初资产与回合构建 —— P0

**2.1 期初资产反推（v1.0 缺失，所有收益率的分母）**
- `period_initial_cash = 首行资金余额 − 首行发生金额`，标 `assumption = back_solved`。
- 首行无论买卖均完整入库，不得丢弃。
- 反推失败（首行无资金余额、或余额为 0 且无发生金额）→ 该区间标 `NAV_UNRELIABLE`，仅输出回合级指标。
- 页面须提示起点口径与影响，不得静默。

**2.2 日终资产与持仓重放**
- 日终资产 = 证券市值（收盘价；停牌用前收盘并标 `stale`）+ 资金余额（按最近发生行前值填充）。
- 每日持仓重放采用摊薄成本（与券商 App 口径一致），另建 FIFO 回合表。

**2.3 FIFO 回合配对（核心实体）**
- 稳定序 = `(交易日期, 原始文件内行号, 摘要, 成交数量, 成交均价)`。
- **回合 pnl（v1.0 缺失股息项）**：
  ```
  pnl = Σ卖出发生金额 − Σ对应买入发生金额绝对值 + 该回合持股数对应股息净额（税后）
  回合收益率 = pnl / Σ买入成本（含费）
  ```
  - 股息按 FIFO 持股数在除息日归属；红利税按差别化税率计入成本。
  - 送转：按公告比例放大数量，总成本不变。
  - 配股缴款：计入买入成本。
  - **禁止二次扣费**：`发生金额` 已含买入费用、已扣卖出费用（见 FR-R5.4）。
- 回合归属区间按**买入日 cohort**（选股域用；见 FR-R4）；卖出侧收益归择时域。
- **验收**：分层抽样 30 回合（加仓/分批减仓/同日多笔/分红/送转/超卖各 ≥3），回合 pnl 差额 ≤`ε_amt`、收益率差额 ≤`ε_r`、FIFO 配对 `trade_id` 集合 100% 一致；跨除权日回合满足一致性等式「买入成本 + 股息 − 卖出净额 = 账单现金流差额」（≤`ε_amt`）；超卖、分红送转、打新均有单测。

**2.4 两套成本口径桥接 + 多账户（P1）**
- 回合按股东账号独立计算（与券商一致）；另提供 `merged_view = true` 合并视图并标注口径。
- **桥接恒等式**（必须输出，不成立则指标域标不一致并列差额）：
  ```
  Σ回合 pnl + 期末浮盈亏 + 股息 + 利息 − 未分摊费用
    = 期末总资产 − 期初总资产 − 净入金        （容差 ≤ ε_amt）
  ```
- 页面对"为什么 App 的成本和这里不一样"给出固定解释文案。

#### FR-R3 净值与收益（TWR + MWR）—— P0

**3.1 净值（份额法，等价于 TWR）**
```
NAV_u,t = (Σ证券市值_t + 资金余额_t) / 份额_t
份额_t  = 份额_{t−1} + CF_t / NAV_u,t          （CF 记为日末发生）
r_t     = NAV_u,t / NAV_{u,t−1} − 1
TWR     = Π(1 + r_t) − 1
年化    = (1 + TWR)^(365 / 自然日数) − 1
```
普通账户 NAV 不含负债；未来支持融资时 `NAV = 资产 − 负债`。

**3.2 外部现金流定义（v1.0 缺失，决定收益对错）**
- **外部现金流（折份额）**：银证转账（转入正/转出负）、配股缴款、场内基金申赎款。
- **内部收益（不折份额）**：股息、红利税、送转、利息归本、佣金/印花税/其他费、融资利息。
- 现金流记为**日末发生**，按当日日末单位净值折份额。

**3.3 MWR（新增，回答"我实际赚了多少"）**
- XIRR 求解：`Σ CF_i / (1+x)^((d_i − d_0)/365) = 0`，CF 含期初投入（负）与期末市值（正）。
- 同时输出 `MWR − TWR` 并给出人话解释（>0 表示资金更多投在盈利期，即出入金时点贡献为正）。

**验收**：给定 fixture 的净值序列与独立实现复算，日收益 diff ≤`ε_r`、区间累计 diff ≤`ε_cum`；构造"月中大额入金遇上涨"样例，TWR 与 MWR 差异方向正确；`NAV_UNRELIABLE` 区间不输出资产类指标。

#### FR-R4 选股能力诊断 —— P0

**4.1 时点一致（point-in-time，新增）**
- 财务/基本面数据按 `announce_date ≤ 决策日` 过滤。数据源无公告日时，以法定披露截止日为保守可用日（年报次年 4/30，季报按披露规则），并记 `data_as_of`、`factor_version`。
- **禁止用"最新财报"评价历史买入**。

**4.2 区间与归属**
- 支持最近一周/月/季度/年度/自定义区间；以**买入日 cohort** 归属区间（买入在区间内才计入该区间选股能力），卖出侧收益归择时域。

**4.3 指标**
- 买入事件 BHAR：`BHAR_h = Π(1 + r_i) − Π(1 + r_b,h)`，`h ∈ {20, 60}` 交易日；需 β 调整或用行业基准；输出均值、中位数、t 值（重叠窗口按事件日聚类）。
- 板块/行业归属（申万一级）、风格分段、持仓期贡献（`Σ w_i,t · r_i,t`）。
- **区分"选得对"（BHAR>0）与"拿得住"（持仓期贡献正）**。

**验收**：给定固定行情快照与合成流水，BHAR 与独立实现 diff ≤`ε_r`；构造"区间内无买入事件"样例，返回空结果而非报错；修改 `as_of` 后不出现晚于该日的财报数据（有断言测试）。

#### FR-R5 择时与绩效体检 —— P0

**5.1 基准规则（v1.0 缺失，决定"跑赢"是否可信）**
- **默认基准：沪深300 全收益**（中证全收益代码 H00300；数据源无全收益序列时用价格指数 + 股息率合成并标 `benchmark = price+div`）。
- 可选基准：沪深300 / 中证500 / 中证1000 / 上证 / 创业板指（均优先全收益）。
- 基准比较须：**同起点归一为 1.0**、**同一交易日历**、**全收益口径**。
- 超额收益须做 **β 调整**：区间日收益 OLS 估 β，β 偏离 1 超过 ±0.2 时提示并追加风格基准；同时输出 β、年化 Jensen α 及 t 值、跟踪误差、`IR = 年化超额 / 年化跟踪误差`。
- 超额须同时给：算术日超额 `Σ(r_p − r_b)` 与几何累积超额 `Π(1+r_p)/Π(1+r_b) − 1`。
- 页面展示顺序：**绝对收益 → 基准超额（带 `benchmark_id` 与 β）**。切换基准前后的历史**不得进入同一条趋势线**。

**5.2 择时指标**
- 追涨分位：`(P_buy − min20) / (max20 − min20)`，用与买入日价格水平**对齐的复权序列**，窗口 `T−20..T−1`（不含 T）；高低相等返回 NULL；并列 `z = (P_buy − mean20)/σ20`。
- 卖飞率：见附录 A（波动率标准化 z 分数）；按 `h ∈ {5,10,20}` 分别给出。
- 买入相对趋势位置（价格 vs MA20/MA60）、卖出后走势。

**5.3 绩效与风格四数字（MVP 第 2 问，须带可信度）**
- 胜率、盈亏比、平均持仓天数、**盈亏集中度**（定义见附录 A）。
- 全部并列 `n` 与 Wilson 95% CI，并给期望值 `E = p·W − (1−p)·L` 与盈亏平衡胜率 `p* = 1/(1+盈亏比)`。
- 胜率须同时输出**已平仓胜率**与**全样本胜率**（含期末浮盈亏）。

**5.4 成本口径（MVP 第 3 问）**
- 费用合计 = 佣金 + 印花税 + 其他费（其他费在数据字典展开为过户费/经手费/证管费/结算费）。
- **禁止二次扣费**：回合 pnl 已由 `发生金额` 内含费用。
- 费用占比（主）= 区间费用 / 区间双边成交额；辅 = 区间费用 / 平均总资产（年化 bp）、区间费用 / 区间 TWR 收益。
- **费用回本门槛** = 年化费用 / 年化平均持仓市值；并输出"费用拖累 = 年化 X bp，相当于吃掉 TWR 的 Y%"。

**5.5 风险指标族（P1）**
- 最大回撤 `MDD = min_t(NAV_t / max_{s≤t} NAV_s − 1)`，并附：回撤持续期、恢复期、水下时间占比、`Ulcer = √mean(DD_t²)`、`Calmar = 年化收益 / abs(MDD)`。
- Sortino、日收益 `CVaR5%`、单票最大亏损占总资产比、单票权重超上限（默认 20%）天数占比。
- 夏普：`(r̄_d − rf_d)/σ_d × √A`；`rf` 参数化默认 1 年期国债或货基 7 日年化（**禁止默认 0**），`A = 244`；附 t 值与 Lo(2002) 自相关调整。
- 资金利用率 = 持仓市值/总资产的时间均值；空仓天数占比；年化单边换手率。

**验收**：固定 fixture 下 TWR/夏普/MDD/费用占比与独立实现 diff ≤`ε_r`；构造"高 β 组合牛市"样例，展示层不得在未标 β 的情况下断言"选股能力强"；N<30 时不输出断言式风格结论。

#### FR-R6 行为偏差诊断 —— P0

**6.1 处置效应（主口径改为 Odean PGR/PLR）**
```
PGR = 已实现盈利笔数 / (已实现盈利笔数 + 期末浮盈笔数)
PLR = 已实现亏损笔数 / (已实现亏损笔数 + 期末浮亏笔数)
DE  = PLR − PGR          （>0 表示处置效应）
```
- 附 bootstrap 95% CI（按回合重抽样 10000 次）。
- 辅助口径：亏损回合平均持有交易日 − 盈利回合平均持有交易日（注明 FIFO 配对影响与 n）。

**6.2 过度交易与分散不足**
- 年化换手率与季度净收益的秩相关（期望为负）、高/低换手季度收益差、费用拖累 bp。
- 仓位 HHI 双口径：`HHI_eq = Σ(单票市值/Σ市值)²`、`HHI_total = Σw_i²`（含现金为一项）；区间给逐日均值 + 最大值 + 期末值。

**6.3 摊平行为**
- 识别"同一标的价格下跌后加仓"笔数与摊平后继续下跌的比例。

**验收**：构造"只卖盈不卖亏"样例，`DE > 0` 且 CI 不含 0；构造"无处置效应"样例，CI 含 0；PGR/PLR 与手算一致。

#### FR-R7 归因诊断（新增，MVP 第 0 问）—— P0

**7.1 P0 · 亏损五因子拆解（M1）**
将区间亏损（或收益）金额拆为：
| 因子 | 口径要点 |
|---|---|
| 选股 | 回合收益中剥离行业/基准 β 后的个股选择贡献 |
| 板块 | 区间内行业配置相对基准的贡献 |
| 买点 | 追涨程度（分位）与买入后 5 日回撤的关联贡献 |
| 卖点 | 卖飞（z 分数）与卖出后走势的贡献 |
| 费用 | 区间费用合计 |

- 输出各因子金额与占比，并给一句结论：「你这个月的亏损主要来自买点（追高），不是选股」。
- **验收**：五因子金额之和与区间总损益差额 ≤`ε_amt`（或明确列出未归属残差）；构造单因子主导的合成 fixture，归因排序正确。

**7.2 P1 · 行业 Brinson（M2）**
- 申万一级 Brinson-Fachler：
  `配置 = (w_p − w_b)(R_b,i − R_b)`；`选择 = w_b,i (R_p,i − R_b,i)`；`交互 = (w_p − w_b)(R_p,i − R_b,i)`。
- 多期用 Carino 平滑链接；`w_p` 取区间平均持仓权重，`w_b` 取基准行业权重。
- 另输出行业偏离 `Σabs(w_p − w_b)/2`、单票风险贡献 `MCTR_i = w_i β_i / β_p`。

#### FR-R8 统计可信度与最小样本 —— P0（新增）

- **样本门槛**：`N < 10` 只输出原始值，不输出任何结论性文案；`N < 30` 的比率必须附 CI；日频 `< 60` 交易日不输出夏普/回撤/IR。
- **区间口径**：比率类指标附 Wilson 95% CI；收益/超额类附 bootstrap（按回合重抽样 10000 次，报 2.5%/97.5% 分位）。
- **多重比较**：核心结论指标固定 8~12 个，其余标 `exploratory`，不进入"行动建议"。
- **表述分级**：只用「样本支持 / 样本不足 / 需更多数据」三种措辞，禁止「你的风格是 XX」式断言。
- **验收**：N=5 的区间确实不输出结论；CI 覆盖率在模拟中接近 95%；同一指标重复计算 diff=0。

### 5.3 交付层

#### FR-D1 只读单页看板 —— P0（v1.0 缺失，本版核心补齐）

一个服务端渲染的单页，首页 5 张卡片：

| 卡片 | 内容 | 下钻 |
|---|---|---|
| ① 净值 | 分段净值曲线 vs 基准（默认沪深300全收益）；**绝对收益排第一**，超额第二；带 `benchmark_id`、β | 逐日净值与出入金明细 |
| ② 四数字 | 胜率（含 CI）/ 盈亏比 / 平均持仓天数 / 盈亏集中度；附 `p*` 与 `n` | 回合列表，点开看 FIFO 配对明细 |
| ③ 费用 | 费用合计、占比（双边成交额）、年化 bp、费用回本门槛 | 按月份/标的的费用明细 |
| ④ 行为 | 处置效应 `DE`、换手、摊平次数、HHI | 触发该指标的回合清单 |
| ⑤ 最赚/最亏 3 笔 | 金额 + 持仓天数 + 追涨分位 + 是否卖飞 | 单笔全链路（买入→卖出→税费） |

- 顶部固定一句**本期结论**：「本月 X 笔，收益 Y 元，相对基准 Z；亏损主要在买点。下月只做一件事：……」
- 数据不可信时卡片显示「口径修复中/数据可疑」占位，**不渲染可能误导的数字**。
- **验收**：M0 可打开骨架页；M1 五卡数据准确（与 API 取值一致）；每个数字均可点开看到口径说明与涉及流水；阻断态不显示收益结论。

#### FR-D2 月度复盘报告 —— P0（v1.0 最大遗漏）

- 一键生成一页报告（HTML，支持打印/存 PDF/导出长图），可保存到本地与备份目录。
- 内容固定结构：
  1. 本月概览（笔数、收益金额与比例、绝对收益、vs 基准、β）；
  2. 亏损归因（五因子占比，最大项高亮）；
  3. 三个最赚钱 / 三个最亏钱的回合（含共性描述）；
  4. 行为观察（处置效应、摊平、换手、费用）；
  5. **重复犯的错**（第 N 次出现同类行为）；
  6. **下月只做一件事**（单条行动建议）；
  7. 口径与数据可信度脚注（`data_as_of`、`n`、是否含可疑数据）。
- 支持"本月报告 vs 上月报告"并列对比（P1）。
- **验收**：M1 可对任一自然月生成报告；报告内每个数字与看板一致（diff=0）；无网络亦可生成；导出文件可在未安装本应用的设备上打开。

#### FR-D3 结论人话层与可追溯下钻 —— P0（新增）

- **每条结论固定三行**：
  1. 结论（人话，1 句）；
  2. 怎么算的（1 句，去掉术语）；
  3. 涉及哪几笔（可点开流水）。
- 全站术语必须过「人话对照」映射（附录 C），页面不出现「血缘/水位线/隔离区/FIFO 回合/metric_id」等裸术语；技术标识只在「口径详情」抽屉中展示。
- 行动建议限定为**复盘与教育口径**，**不得构成具体投资建议**（不出现"建议买入/卖出某标的"）。
- **验收**：任取 10 个页面数字，均有对应三行说明；术语扫描无裸术语；建议文案经合规口径检查（无标的级买卖建议）。

#### FR-D4 交易日志与闭环 —— P0 建实体 / P1 闭环

**4.1 日志一等实体（v1.0 完全缺失）**
- 字段：标的、关联回合、买入理由（结构化标签 + 自由文本）、计划（目标价/止损/持有预期）、情绪评分、事后对照结论、是否兑现。
- 买入后可一键"30 秒记一句理由"。

**4.2 三阶闭环（P1）**
- 卖出后自动弹出「当初这个理由还成立吗？」；
- 季度输出「我说的 vs 实际发生的」：判断准确率、理由类型的平均收益、情绪评分与收益的关系。

**验收**：日志可增删改查并关联到回合；卖出后确实触发对照提示；季度汇总可生成。

#### FR-D5 纵向趋势对比 —— P1（新增）

- 按季度/月度输出胜率、盈亏比、处置效应 `DE`、费用率、换手率的**趋势线**，回答"我在变好还是变差"。
- 基准或口径切换处必须断点标记，不得跨口径连线。
- **验收**：趋势线与分季度快照数值一致；口径变更处有断点。

#### FR-D6 行为规则卡与提醒 —— P1（新增）

- 将行为指标翻译为**可触发规则**（示例模板，用户可编辑阈值）：
  - 「浮亏 >10% 且持有 >5 个交易日」→ 提醒复核买入理由；
  - 「单月换手率超过去 12 个月中位数 2 倍」→ 提醒费用拖累；
  - 「连续 3 笔在同一板块亏损」→ 提醒集中度。
- 无法实时则产出**周报式提示**：「上周你有 3 次差点重犯：……」
- **验收**：规则命中可回放验证；提醒内容不含买卖建议；可关闭。

#### FR-D7 对话复盘问答 —— P1

**7.1 取数与回答**
- 自然语言提问 → Agent 通过工具调用指标 API 取数作答。
- 起始模型 GLM-4.5-Air，效果不佳可切换；**工具强制取数**，禁止模型自行编造数字。

**7.2 上下文管理（简化）**
- 固定问题按钮（10 个高频问题）+ 自由输入；单轮检索 + 必要多轮；v1.0 的"五层 Token 预算 + 滚动摘要"降级为"基础会话压缩"。

**7.3 隐私与金额可见性（v1.0 自相矛盾处修订）**
- **金额由本地工具计算后填入回答模板，LLM 只负责组织语言与解释**；因此无需向远程 LLM 传输金额与账号。
- 提供用户可见开关：「允许 AI 读取我的持仓金额（仅本机）」，默认开启；真实脱敏发生在**远程出站那一刻**，并在回答底部标注「本次回答：本地计算/已脱敏」。
- 因此 G3/G4 与隐私不冲突：关闭网络时金额类问题仍可作答。

**7.4 日志收集**
- 会话、消息、每次工具调用（入参/浓缩结果/完整结果/耗时）全量落库；应用日志 `request_id` 贯穿。
- **验收**：回答中每个数字可点开看到来源（本地计算结果或数据源返回结果）；长会话（>20 轮）结论不丢失；断网状态下金额类问题仍可答；出站请求中不含金额与账号（有断言测试）。

#### FR-D8 通知与移动端查看 —— P2

- 月报生成后可推送提醒；提供手机可打开的报告分享页（静态文件即可，不做 App）。
- **验收**：手机浏览器可打开导出的报告；提醒可关闭。

## 附录 A：关键计算口径（公式化，可直接实现）

> 全局常量：`A = 244`（年化交易日）、`ε_amt = 0.01 元`、`ε_r = 1bp`、`ε_cum = 5bp`、`rf` 参数化（默认 1 年期国债或货基 7 日年化，**禁止默认 0**）、`definition_version` 随口径变更递增。

| # | 术语 | 口径 |
|---|---|---|
| A1 | 期初资产 | `period_initial_cash = 首行资金余额 − 首行发生金额`；标 `assumption = back_solved`；失败则 `NAV_UNRELIABLE` |
| A2 | 外部现金流 | 仅含银证转账、配股缴款、场内基金申赎款；记为日末发生 |
| A3 | 内部收益 | 股息、红利税、送转、利息归本、佣金/印花税/其他费、融资利息（不折份额） |
| A4 | 单位净值 | `NAV_u,t = (Σ证券市值_t + 资金余额_t) / 份额_t`；`份额_t = 份额_{t−1} + CF_t / NAV_u,t`；普通账户不含负债 |
| A5 | TWR | `TWR = Π(1 + r_t) − 1`，`r_t = NAV_u,t / NAV_{u,t−1} − 1`；年化 `(1+TWR)^(365/自然日) − 1` |
| A6 | MWR | XIRR：`Σ CF_i/(1+x)^((d_i−d_0)/365) = 0`；同时输出 `MWR − TWR` 及解释 |
| A7 | 回合（Round-Trip） | 同一证券 FIFO 配对的一次完整买入→卖出；稳定序 `(交易日, 文件行号, 摘要, 数量, 均价)` |
| A8 | 回合 pnl | `Σ卖出发生金额 − Σ对应买入发生金额绝对值 + 该股数对应股息净额（税后）`；收益率 `= pnl / Σ买入成本（含费）` |
| A9 | 除权处理 | 送转按公告比例放大数量、总成本不变；配股缴款计入买入成本；跨除权日须过一致性等式（≤`ε_amt`） |
| A10 | 胜率（已平仓） | 已平仓回合 `pnl>0` 占比；并列 **全样本胜率** `= (已实现盈利 + 期末浮盈)/(已平仓 + 未平仓)`；附 n 与 Wilson 95% CI |
| A11 | 盈亏比 | `平均盈利金额 / abs(平均亏损金额)`，并列 median 版 |
| A12 | 期望值与盈亏平衡胜率 | `E = p·W − (1−p)·L`；`p* = 1/(1+盈亏比)` |
| A13 | 平均持仓天数 | 交易日计：卖出日 − FIFO 对应买入日（同日记 1）；并列 median、自然日版、资金占用天数（摊薄加权） |
| A14 | **盈亏集中度（v1.0 无定义，本版补齐）** | 主：`Top3 盈利回合盈利 / 全部盈利回合盈利`；辅：`CR1 = 最大单笔盈利 / 全部盈利之和`、盈利回合 pnl 的 Gini；分母仅含 `pnl>0` |
| A15 | 处置效应 DE | `DE = PLR − PGR`；`PGR = 已实现盈利笔数/(已实现盈利+期末浮盈笔数)`；`PLR` 同理；bootstrap 95% CI；`DE > 0` 为处置效应。辅助：`亏损回合均持 − 盈利回合均持` |
| A16 | 卖飞率 | `z = (R_after − R_bench,h) / (σ_i日·√h) > 1.0`，`h ∈ {5,10,20}`，按卖出金额加权；`σ_i日` 取卖出日前 60 日日收益标准差；`R_bench,h` 为 β 调整基准收益（前 250 日 OLS）；停牌>50%/退市/未走完剔除并计 `pending_window` |
| A17 | 追涨分位 | `(P_buy − min20)/(max20 − min20)`，复权序列与买入日价格水平对齐，窗口 `T−20..T−1`（不含 T），高低相等返回 NULL；并列 `z = (P_buy − mean20)/σ20` |
| A18 | 最大回撤族 | `MDD = min_t(NAV_t / max_{s≤t} NAV_s − 1)`；附持续期、恢复期、水下时间占比、`Ulcer = √mean(DD_t²)`、`Calmar = 年化收益/abs(MDD)` |
| A19 | 仓位 HHI | `HHI_eq = Σ(市值_i/Σ市值)²`；`HHI_total = Σw_i²`（含现金为一项）；区间聚合给逐日均值 + 最大值 + 期末值 |
| A20 | 夏普 | `(r̄_d − rf_d)/σ_d × √A`，`A = 244`，`rf` 参数化；附 t 与 Lo(2002) 自相关调整 |
| A21 | 费用合计与占比 | 费用 = 佣金 + 印花税 + 其他费（其他费展开为过户费/经手费/证管费/结算费）；**禁止二次扣费**；占比（主）= 区间费用/区间双边成交额；辅 = /平均总资产（年化 bp）、/区间 TWR 收益 |
| A22 | 费用回本门槛 | `年化费用 / 年化平均持仓市值`；并输出"费用拖累 = 年化 X bp，相当于吃掉 TWR 的 Y%" |
| A23 | 基准超额 | 默认沪深300全收益；同起点归一、同一日历、全收益；算术日超额 `Σ(r_p−r_b)` 与几何累积超额 `Π(1+r_p)/Π(1+r_b) − 1` 并列；附 β、年化 α 及 t、跟踪误差、`IR = 年化超额/年化跟踪误差` |
| A24 | BHAR | `BHAR_h = Π(1+r_i) − Π(1+r_b,h)`，`h ∈ {20,60}`，β 调整或行业基准；输出均值、中位数、t 值（事件日聚类） |
| A25 | Brinson（P1） | `配置 = (w_p−w_b)(R_b,i−R_b)`；`选择 = w_b,i(R_p,i−R_b,i)`；`交互 = (w_p−w_b)(R_p,i−R_b,i)`；多期 Carino 链接 |
| A26 | 统计门槛 | `N<10` 只出原始值；`N<30` 附 CI；日频 `<60` 交易日不出夏普/回撤/IR；核心指标固定 8~12 个，其余 `exploratory` |
| A27 | dedupe_key | `hash(user_id + 归一化股东账号 + 日期 + 证券代码 + 摘要 + 数量 + 均价 + 发生金额)`；空股东账号归一为哨兵值 `UNKNOWN`；同键多笔按出现次序计数去重（bag-level），**不含 `资金余额`**（避免交割单无该列时失效，也避免同日同额多笔碰撞） |

## 附录 B：数据字典与去重规则

**B1 账单字段（13 个固定字段 + 2 可选）**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 日期 | date | 是 | 多格式解析，统一存 UTC+8 本地日 |
| 币种 | enum | 是 | 本期仅 `CNY` |
| 股东账号 | text | 否 | 可空（如利息归本）；展示脱敏，输入侧原文本地加密存储而非哈希（保留可还原能力） |
| 证券代码 | text | 否 | 打新/资金流水可空 |
| 证券名称 | text | 否 | |
| 摘要 | text | 是 | 经规则表分类 |
| 成交数量 | decimal(18,4) | 是 | 0 表示非成交 |
| 成交均价 | decimal(18,6) | 是 | |
| 佣金 / 印花税 / 其他费 | decimal(18,2) | 是 | 其他费展开为子项 |
| 发生金额 | decimal(18,2) | 是 | 买入为负、卖出为正（含费） |
| 资金余额 | decimal(18,2) | 否 | 缺失则对账降级 |
| 操作理由 / 备注 | text | 否 | 可选 |

**B2 去重规则（修订 v1.0 缺陷 R-B8）**
- 行级幂等：同 `dedupe_key` 的多行按**出现次数（bag）**比对，仅插入差额部分；**不做单行覆盖**。
- 股东账号为空的行不得因哈希相同而互相吞并（归一为哨兵值 + 计数去重）。
- `资金余额` 不进入 key（交割单无此列，且同日同额多笔会碰撞）。

**B3 导入批次**
- `import_batch(id, filename_hash, mode, total_rows, inserted, skipped, quarantined, created_at, revoked_at)`
- 撤销 = 对该批次 `inserted` 的行批量软删，`revoked_at` 落时间。
