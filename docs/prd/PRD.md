# 个人交易复盘体系 · 产品需求文档（PRD）

> 版本：v1.0 ｜ 日期：2026-10-18

---

## 1. 背景与问题

### 1.1 背景

用户（个人投资者）持有完整的股票生涯流水明细（券商导出交易账单），希望借助软件能力分析与提升自己的**股票选择**与**交易执行**水平。

### 1.2 核心洞察（头脑风暴结论）

流水明细的核心价值**不在对账**，而在于把三个维度拆开独立度量：

| 维度 | 度量问题 |
|---|---|
| **选股能力** | 买入的股票本身好不好？（财务数据如何、买入后超额收益率(与指数收益进行对比)、板块归属、风格分段） |
| **择时能力** | 买点和卖点好不好？（买在阶段上升趋势中还是在下降趋势中、追涨分位、卖飞率、卖出后走势） |
| **行为偏差** | 是否在系统性犯同样的错？（处置效应、摊平、频率-收益负相关） |

### 1.3 原始诉求（MVP 四问，产品起点）

1. 净值曲线 vs 上证指数/创业板指数/科创板指数 ——我到底跑赢了吗？
2. 胜率 × 盈亏比 × 平均持仓天数 × 盈亏集中度 ——四个数字定性我的风格
3. 手续费累计占比——交易成本是朋友还是敌人？
4. 处置效应检测——赚钱仓和亏钱仓的持有天数差

**产品定位**：在 MVP 四问之上，构建完整的「数据底座 → 2大能力（选股、择时） → 行动闭环（行为诊断、提升建议）」个人交易复盘体系。

## 2. 产品目标

| 编号 | 目标 | 可验证的成功标准 |
|---|---|---|
| G1 | 把券商流水从"对账单"升级为"交易能力度量系统" | 2大能力域指标全部可 API 输出，且与手工抽查（≥10 回合）一致 |
| G2 | 数据可信 | 每次账单导入自动对账；任一指标可追溯到原始流水行 |
| G3 | 复盘以对话完成 | 用自然语言提问"我本月为什么亏"，回答中每个数字可追溯到指标结果 |
| G4 | 数据自主可控 | 全链路本地/内网部署，账单数据不外流（LLM 出站经隐私过滤） |

## 3. 用户与使用场景

**用户**：单一个人用户（系统 seed 唯一记录，`name='root'`、`user_id=100000`）。**无账号密码登录、无权限体系**——`user_id` 只是数据分区标签，服务仅绑定本机/内网。

**核心使用场景：**

```
每月导出账单 → 导入账单系统（增量去重）
                ↓ 自动：解析 → 分类 → 入库 → 对账
复盘系统水位线同步 → 重算指标（FIFO 回合、净值、五域指标）
                ↓
周五晚复盘：对话问答（"这个月哪个板块亏最多？""我卖飞的票有多少？"）
                ↓
对关键回合写交易日志（买入理由 / 计划 / 情绪 / 事后对照）
                ↓ 每月
生成月度复盘报告 → 下月行为改进
```

## 4. 产品组成

| 系统 | 一句话定位 | 关键需求特征 |
|---|---|---|
| **交易账单系统**（Trade Ledger Service） | 交易数据唯一事实源 | 解析入库、三种更新方式、软删可追溯、对账自证、变更流 API |
| **个人交易复盘系统**（Trading Review Service） | 交易能力度量 + 对话复盘 | 五大能力全部 API 化（无可视化）、对话问答 Agent、上下文管理、日志收集 |

两系统同仓库（uv workspace Monorepo）开发，PostgreSQL 同实例分库（`ledger` / `review`）。

## 5. 功能需求

> 优先级：P0（M0–M1 必须）/ P1（M2）/ P2（M3–M4）。验收标准为该需求"完成"的判定依据。

### 5.1 交易账单系统

产品层面仅支持A股华泰证券普通账户交易账单数据。程序上可以考虑区分A股/港股/美股、券商、普通/融资账户。
每个用户的起始账单数据为第一支股票买入，如果导入账单时起始数据不是买入，则不存储该账单数据。
真实账单格式支持（`.xls`/`.xlsx`/`.csv`）。

#### FR-L1 用户数据分区 —— P0
- 系统 seed 唯一用户（`name='root'`、`user_id=100000`）；所有数据带 `user_id`（BIGINT，从 100000 起自增）；不做登录与权限。
- **验收**：API 均接受 `user_id` 参数（默认 `100000`）；`users` 表仅一行 seed 数据。
- 后续对C端用户开放后再增加密码、角色与权限的功能

#### FR-L2 账单导入与部分更新 —— P0
- 支持 13 个固定字段的账单（日期/币种/股东账号/证券代码/证券名称/摘要/成交数量/成交均价/佣金/印花税/其他费/发生金额/资金余额），Excel/CSV。
- 三种更新模式：
  - **全量导入**：重复行自动跳过（行级幂等）；
  - **增量更新**：定期导出新区间账单，重叠区间自动去重；
  - **区间替换**：账单修正/补录，指定日期区间内以新账单为准。
  - 单条插入：以接口的形式插入单条数据，根据行幂等性，如果有重复的则替换。
- **无批次表**：导入不落批次元数据；更新日志 = 按 `trades.created_at` 分时段聚合查询。
- 股东账户字段在导入时进行hash加密存储
- **验收**：重复上传同一文件 0 新增；区间替换后旧数据保留（软删）且新数据生效；导入历史可按 created_at 聚合查出。

#### FR-L3 交易数据维护 —— P0
- 单行人工接口修正（PATCH）、软删（DELETE，`deleted=true`）、恢复；删除历史永不物理清除。
- **验收**：软删行不参与下游（变更流以墓碑形式带出），可恢复。

#### FR-L4 摘要分类与隔离区 —— P0
- 「摘要」字段经可配置规则表分类：买入/卖出 → 交易流；分红/送股/银证转账等 → 公司行为流；未匹配 → **隔离区并在导入响应中告警，绝不静默丢弃**。
- **验收**：所有摘要类型可归类；未知摘要 100% 进隔离区；规则可经 API 维护。

#### FR-L5 对账自证 —— P0
- 利用账单自带逐行「资金余额」做**现金余额链校验**（上一行余额 ± 发生金额 ≈ 本行余额），断链精确定位到行。
- 对账 FAIL 不阻断入库，但结果可被复盘系统查询。
- **验收**：断链样例 fixture 检出并给出断点 trade_id 与期望/实际值。

#### FR-L6 查询与变更流 API —— P0
- 流水分页查询（账户/代码/日期/方向/是否含已删）。
- **变更流**：`GET /trades/changes?since=<水位线>` 返回该时刻后被新增/修改/软删的行（复盘系统增量同步专用）。
- **验收**：任一时刻起点的变更拉取结果与实际数据变更一致（含墓碑）。

### 5.2 个人交易复盘系统

#### FR-R1 账单数据同步 —— P0
- 按用户（默认 `100000`）以水位线增量拉取账单变更流，落地本地镜像（含软删墓碑）；同步前检查账单系统对账状态，FAIL 则指标域标记不可用并带原因。
- **验收**：乱序 updated_at、墓碑、重复推送均正确处理；镜像与源端最终一致。


#### FR-R2 数据底座能力 —— P0
- 定时任务每日增量构建（有新增清仓卖出时）历史持仓：FIFO 回合配对（加仓/分批减仓/同日多笔按稳定序），产出**回合表**（核心实体：一次完整买入→卖出）；
- 每日持仓重放（摊薄成本，与券商口径一致）；净值计算（份额法处理出入金，不扭曲收益率）。
- **验收**：配对结果与手工核算一致；超卖、分红送转等边界有单测；对账闸门不通过则阻断指标。

#### FR-R3 选股能力诊断 —— P0（纯流水和调用 akshare[https://github.com/akfamily/akshare] 接口计算） 
- 可按最近一周、月、季度、年度或者自定义时段的交易数据进行选股能力诊断，诊断结果入库
- 根据时间范围内，以单个股票的的回合数据进行计算，具体指标可以查询akshare的接口。
- **验收**：接口调用成功，已有结果直接返回数据，没有诊断过能生成诊断数据

> 可通过此文档上的指导查询所有接口列表：https://akshare.akfamily.xyz/registry.html

#### FR-R4 择时能力诊断 —— P0（纯流水和调用AlphaFeed的行情数据计算）
- 可按最近一周、月、季度、年度或者自定义时段的交易数据进行绩效体检，体检结果入库
- 根据时间范围内的账单计算：总体收益率/总体最大回撤/夏普值/交易胜率/交易收益占比（非股息收益）/费用占比。
- 以单个股票的的回合数据进行计算：卖出后5个交易日、10个交易日、20个交易日的涨跌幅度、单回合收益率，计算结果以JSON存放到字段里。
- **验收**：接口调用成功，能生成体检数据；能够有诊断列表接口可以看到所有诊断记录


#### FR-R5 对话复盘问答 —— P1（产品最终形态）
- 自然语言提问 → Agent 通过工具调用能力 API 取数作答；
- LLM先选择GLM-4.5-Air，如果模型回答效果不好可以切换模型；
- **上下文管理**：Token 预算 + 滚动摘要压缩，长会话不丢已确认结论；
- **日志收集**：会话、消息、每次工具调用（入参/浓缩结果/完整结果/耗时）全量落库；应用日志 request_id 贯穿；
- **隐私闸门**：LLM 出站上下文剥离资金绝对值与账号（只传比例/分位）；
- **验收**：回答中每个数字可追溯来源（来源可以是计算结果、akShare接口获取结果）；长会话（>50 轮）摘要后结论不丢失。

## 6. 非功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-1 | 隐私 | 全链路本地/内网；账单原件仅本地归档；LLM 出站经 PrivacyFilter；行情请求零账户信息 |
| NFR-2 | 数据可信优先 | 每次导入自动对账；指标计算前置对账闸门；任一数字可追溯（指标血缘：computed_at + params） |
| NFR-3 | 幂等与可重放 | 导入行级幂等；派生数据可全量重建；软删保留历史 |
| NFR-4 | 无鉴权（明确取舍） | 内网单用户场景，`user_id` 非身份凭证；未来加鉴权仅需 API 中间件，表结构不变 |
| NFR-5 | 工程一致性 | uv workspace Monorepo：契约同源（packages/contracts）、唯一锁文件、CI 路径过滤、Conventional Commits |
| NFR-6 | 测试 | 回合配对/净值/对账/同步/上下文管理 100% 单测覆盖，合成流水 fixture 含全部边界 |
| NFR-7 | 依赖 | 强依赖akshare库，在做架构设计时可以考虑对部分数据进行本地化存储 |

## 9. 风险与依赖

| 风险/依赖 | 影响 | 应对 |
|---|---|---|
| akshare 限频/不可用 | 归因类指标不可算 | 本地缓存永久化 + 断点续传；降级"仅 P0 指标可用"并明示；适配器预留灾备行情源 |
| 账单摘要出现新类型 | 解析漏数 | 隔离区 + 告警；补规则后 REPLACE_RANGE 重导区间 |
| 账单区间空洞（漏导） | 余额链断链 | 对账精确定位断点，用区间替换修复 |
| LLM 幻觉 | 复盘结论失真 | 工具强制取数 + 回答须引用 metric_id + meta 留痕 + 低温度 |
| 长会话上下文溢出 | 问答质量下降 | 五层 Token 预算 + 滚动摘要 |
| 前复权因子随除权变化 | 历史收益率失真 | 除权检测触发缓存失效重拉 |

## 附录：关键计算口径（产品需求的精确化）

| 术语 | 口径 |
|---|---|
| 胜率 | 已平仓回合 pnl>0 占比（含费） |
| 盈亏比 | 平均盈利回合盈利 ÷ 平均亏损回合亏损绝对值 |
| 处置效应系数 | 亏损回合平均持有交易日 − 盈利回合平均持有交易日 |
| 卖飞率 | 平仓后 20 交易日基准调整涨幅 >5% 的回合占比 |
| 追涨分位 | (买入价 − 近20日最低) ÷ (近20日最高 − 近20日最低)，不复权价 |
| 最大回撤 | nav 峰值到后续谷值最大跌幅 |
| 仓位 HHI | Σ(单票市值/总市值)²，每日计算 |
| 回合（Round-Trip） | 同一证券 FIFO 配对的一次完整买入→卖出过程，系统核心实体 |
| dedupe_key | hash(user_id+股东账号+日期+证券代码+摘要+数量+价格+发生金额+资金余额) |
